## `parquet/` — the bar store

- Not in git: rebuilt by a re-pull (the daily refresh, or the two pullers below), not by a checkout.
- Fresh checkout (a worktree, a clone, CI): `npm run bars:snapshot` restores the `ff29a732` snapshot, which is enough for smoke and the tests; it refuses unless the store path is absent or an empty directory, so a symlink, a file or a partial restore must be moved aside first.
- Layout: `parquet/venue=<venue>/symbol=<SYMBOL>/year=<YYYY>/data_0.parquet`, one file per venue, symbol and calendar year (doc 66 D2). Venues are `alpaca` (US) and `saxo` (LSE). Columns `date` (DATE), `open`, `high`, `low`, `close`, `volume`, `raw_close` (all DOUBLE); `venue`, `symbol` and `year` live in the path.
- Reader and writer: `server/providers/bar-store/parquet-bar-store.ts` over DuckDB (`@duckdb/node-api`). A write replaces each written symbol whole and leaves the others alone. DuckDB runs single-threaded so the same bars always produce the same bytes.
- Migrated from the per-symbol CSVs on 2026-09-25 (doc 67 Step 3b): 746 alpaca series (1,761,296 bars) and 22 saxo series (87,971 bars, 87,934 after the 2026-09-29 shape repair below), every series read back identical to the CSV, and the doc 70 verdicts re-ran byte-identical to a CSV re-run on the base commit. The CSVs are in git history before that commit.
- The pullers round prices to four decimals before writing, as the CSVs did.

## `alpaca/` — US daily bars (in `parquet/venue=alpaca`)

- Source: Alpaca Market Data `GET /v2/stocks/bars`, `timeframe=1Day`, `feed=sip`, pulled twice per symbol — `adjustment=all` for OHLCV and `adjustment=raw` for the `raw_close` column (whole-share sizing needs the price actually quoted that day).
- Window: 2016-01-04 to 2026-09-23 (`manifest.json` carries `start`, `end`, `fetched_at`, per-symbol first/last date and bar count, and the `missing` list).
- Universe: every ticker that was an S&P 500 member on or after 2016-01-04 per `sp500-constituents.csv` (745 names) plus `SPY` as the trading-calendar reference. 746/746 symbols returned bars; `missing` is empty. Tickers with a dot (`BRK.B`) are requested as written and then dot-stripped.
- This directory keeps only `manifest.json`; the bars are in the store.
- Implausible prints (#1889): the daily refresh (`server/apps/v2/bar-refresh.ts`) quarantines, that is drops, any bar whose open, high or low lies more than 2× beyond the previous, next and own closes, so the name skips that session; no price is repaired or invented. Over the 1,761,296 stored bars that flags exactly 4, all glitches (SPY 2026-02-02 low 68.47, MRK 2021-06-11 low 12.92, VZ 2026-01-08 low 10.09, BBBY 2016-10-27 high 108.26); the largest genuine extremes are FRC 2023-03-13 at 1.78× and GME 2021-01-28 at 1.73×. The store still holds the 4 until the next refresh rewrites those series. Each quarantine is a warn-level `v2_bar_quarantined` journal line; a SPY bar inside the last five sessions aborts the run instead, because SPY is the US session calendar.
- Puller: `server/tools/backtest/momentum/pull-alpaca-bars.ts` (needs `ALPACA_API_KEY`/`ALPACA_API_SECRET` via `--env-file`; `--store` overrides the store root). <!-- cite-exempt: historical — deleted in v1 teardown wave 1 (#1748); preserved at commit 09012b29 (last main commit before the deletions) -->

## `fx/gbpusd-boe-xudluss.csv` — USD per GBP

- Not in git since #2000 (David, 2026-10-02), because the paper run appends to it daily. The tracked copy is `fx/gbpusd-boe-xudluss.snapshot.csv`, the file as it stood when it stopped being tracked (to 2026-09-24). `npm run bars:snapshot` copies it into place when the live file is absent, before the Parquet restore. Every reader of the file does the same on its first read, through `readSeededFile` (`server/shared/seeded-file.ts`): `composeV2Root` (the paper run and the signals process), the BoE refresh leg, the dashboard and Telegram FX readers, the replay, backtest and cost-fidelity CLIs and the two momentum tools. So a fresh checkout, CI and every Mac process after the pull that removes the tracked file start from it, without waiting for a paper run. Neither path overwrites a live file. Smoke and the tests that check the committed series read the snapshot; tests that run a real reader point it at a temporary copy. A seeded file is behind BoE; the next refresh refetches from 14 days before its last row and appends the rest.
- Source: Bank of England IADB series `XUDLUSS` (spot, US dollars into sterling), daily from 2010-01-04 to 2026-09-24, fetched 2026-09-25 via `https://www.bankofengland.co.uk/boeapps/iadb/fromshowcolumns.asp?csv.x=yes&Datefrom=01/Jan/2010&Dateto=now&SeriesCodes=XUDLUSS&CSVF=TN&UsingCodes=Y&VPD=Y&VFD=N` (the endpoint redirects; fetch with `curl -L`). Open Government Licence v3.0. The 2026-09-23 pull from 2015-12-01 is a strict subset of this file.
- Refresh (#2000): the bar refresh's fourth leg, `server/apps/v2/fx-refresh.ts`, refetches from 14 days before the last row on every non-dry paper run and appends only newer rows, as BoE wrote them; the overlap is counted from BoE's first returned row, so it holds whether `Datefrom` is inclusive or not, and every overlap row must match the file. A revised or missing overlap row, no overlap row at all, a response not ending in a newline (a cut-off last row), an unparseable response or no answer within 30 s refuses the append (`v2_fx_refresh_failed`) and leaves the file as it was. The request sends a browser `User-Agent`; whether the live IADB answers it from the Mac is unproven until the probe in #2002.
- Use: doc 70 ruling (j) — each calendar year converts at the last published rate on or before 1 January, so FX never enters the loss budget. The sibling splice (`saxo-aux/`) converts each USD bar at the same-day fix or the last fix on or before it.

## `saxo/` — LSE daily bars (in `parquet/venue=saxo`)

- Source: Saxo OpenAPI live gateway `GET /chart/v3/charts`, `Horizon=1440`, `Count=1200`, paged back with `Mode=UpTo&Time=<earliest>` until a short page; `ChartInfo.DelayedByMinutes` 15. Pulled 2026-09-25 with a read-only token.
- Prices in **GBP after the hygiene step** (`server/providers/bar-store/bar-hygiene.ts`): GBX-quoted lines are scaled by 0.01 once at ingest, checked against each instrument's `PriceToContractFactor` (0.01 GBX, 1 GBP); GBP-quoted lines (VMID, IGLT, INXG, SLXX, VUTY) are stored as quoted. `PriceToContractFactor` only vouches for today's unit, so every series is then scanned for a mid-series unit change: a close/close ratio inside (90, 110) or its inverse is a unit break and the earlier segment is rescaled to the latest unit (found and fixed: SGLN ×100 at 2017-06-23, IGLT ÷100 at 2011-10-20, VMID ÷100 at 2014-10-17, and a three-bar ×100 spike in COMF 2010-04-06→08); a ratio beyond 3× that is not a unit break refuses the pull (none did); adjacent moves beyond ±35% are counted as suspect flips and left in place (CUS1 65 in 2011-08→2013-05, SPGP 65 in 2012, CPJ1 2 in 2014-11, VUTY 2 in 2016-03 — all before the 2016-06-21 window); weekend-dated bars (2007–08 on ISF, IEEM, IJPN; IESU 2017-01-01) and the fetch-day bar (2026-09-25, a partial session) are dropped. Per-line findings are in `manifest.json` under `symbols.<TIDM>.hygiene`. Saxo chart samples also carry open or close outside their own high-low range (4,556 of the 87,971 stored bars, 18 of them with high below low; Alpaca has none, and its 13,884 flat o=h=l=c bars are legitimate), and 43 bars with per-field unit or currency-mixed prices (#1838, a re-pull does not fix it because Saxo's response carries the defect). `repairBarShape` in `bar-hygiene.ts` runs after the unit-break step on Saxo lines only: an open, high or low whose ratio to the median of the other three prices is inside (90, 110) or its inverse is rescaled by 100 or 0.01 (6 fields: IGLT 2011-08-23, 2011-09-20, 2011-09-28 and 2016-10-27, INXG 2016-11-23, SPOG 2017-11-20); a bar whose four prices still span more than 1.4× is dropped (37 bars, dates in `symbols.<TIDM>.hygiene.shape_repair.dropped_glitch_dates`, SPGP and CUS1 2012 GBPUSD-mixed spans among them); then high and low are widened to cover open and close (4,543 bars). Close and `raw_close` are never changed; an open can be rescaled by the unit rule or replaced by the neighbour step (the 6 rescaled fields above are all highs or lows; the neighbour re-run below changed 13 opens). The one-off `server/tools/backtest/momentum/repair-saxo-bar-shape.ts` applied this to the stored parquet on 2026-09-29, leaving 87,934 Saxo bars and zero shape violations in either venue; it is idempotent per code version and against its own manifest: replaying an already-recorded repair on a pre-repair store leaves the manifest byte-identical. It also refreshes the manifest: every Saxo line carries `hygiene.shape_repair` with the earlier counts kept, and the manifest `hygiene` note is replaced, not appended, with `SHAPE_REPAIR_MANIFEST_NOTE`. Since #1904 the rule also runs a neighbour step between the unit step and the span rule: an open, high or low more than 1.1× beyond the previous, next and own closes is replaced by the close (the largest genuine extreme measured on the raw lines is INXG 2022-09-28 at 1.085×, the smallest named glitch IUSA 2020-03-09 at 1.120×; calibrated on 1× ETFs, not for CFD single-stock underlyings). On the raw series that keeps 25 of the 37 dropped bars, SPOG 2020-03-09 and SPGP 2020-03-17 among them, leaves 12 dropped, and replaces fields on 58 bars (25 from 2016-06-21 on); a glitched close such as IEEM 2014-06-20 is never changed. The one-off was re-run with the neighbour step on 2026-10-01 (#1969, David: "fix it") over the 87,934 stored bars: 32 bars on 12 lines changed (CUS1 1, IEEM 2, IESU 1, IGLT 4, IITU 1, IJPN 3, INXG 1, ISF 2, IUSA 4, SPGP 10, SPOG 2, UIFS 1; 18 of them from 2016-06-21 on), as 45 field replacements (13 opens, 21 highs, 11 lows) and 11 high-low ranges re-widened; no close, `raw_close`, volume or bar count changed, and no bar was rescaled or dropped (the 37 already-dropped bars cannot be recovered from the stored series, so the store keeps those drops; the 25 the neighbour step would have kept need a re-pull). Per-bar entries are in `symbols.<TIDM>.hygiene.shape_repair.neighbour_repairs`. The pinned `bars:snapshot` (`ff29a732`) is the pre-re-run store, so it does not carry these 32 changes; the live store gets them by running the script on it, and the daily refresh (`server/apps/v2/saxo-bar-refresh.ts`) applies the neighbour step on every re-pull and also refuses to write a line whose drop, rescale or replacement falls in the last five sessions. `ParquetBarStore.write` now refuses any bar with open or close outside high-low, for both venues. `raw_close` equals `close` (no adjustment is applied — Saxo's closes are price-only, see `manifest.json` `checks.distribution_adjustment`: the ISF/CUKX ratio drifts −3.76%/yr, which is the dividend yield). <!-- cite-exempt: historical — deleted in v1 teardown wave 1 (#1748); preserved at commit 09012b29 (last main commit before the deletions) -->
- Lines: 22 of the 24 in doc 70 §2.2, 2000-04-28 (ISF) to 2026-09-24. `manifest.json` carries `calendar_reference` (ISF), `window_start` (the latest first bar among included lines, 2016-06-21, binding line IITU), per-line `first`/`last`/`bars`/`density`/`half_spread_bps`/`is_complex`/`hygiene`, and `excluded` for IHCU and CMFP, whose sibling splice failed the 1 bp/day tolerance set in the session brief (doc 70 §10.3). The runner refuses a series that still carries a unit break. This directory keeps only `manifest.json`.
- Puller: `server/tools/backtest/momentum/pull-saxo-bars.ts` (`--token-file` points at the live token store, `--spreads`/`--fx` default to the files here, `--store` overrides the store root). Lines are declared in `server/providers/saxo-bars/lse-lines.ts`. <!-- cite-exempt: historical — deleted in v1 teardown wave 1 (#1748); preserved at commit 09012b29 (last main commit before the deletions) -->
