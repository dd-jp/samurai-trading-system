# Signals sleeve — spec (v2, #1941)

Authority: David's rulings of 2026-09-30 on [#1941](https://github.com/dd-jp/samurai-trading-system/issues/1941), recorded in `docs/research/66-v2-grill-decisions.md` ("Rulings of 2026-09-30 — external signals sleeve") and `docs/adr/0001-samurai-v2.md` §2.3 and §5 item 22. The sleeve is built in two PRs: the endpoint and store (built), then the sleeve, books, processor and cycle integration (built, the second #1941 PR). David's rulings of 2026-10-05 on [#2024](https://github.com/dd-jp/samurai-trading-system/issues/2024#issuecomment-6001591570) (doc 66, "Rulings of 2026-10-05 — signals sleeve (#2024)"; ADR §5 item 25) settle the four points #1941 left recorded but not ruled. Two of them are built (the veto-rate fault and the retry). David's rulings of 2026-10-08 on #2024 (doc 66, "Rulings of 2026-10-08 — signals universe and shadow fill") answer what the other two left open, and both are built (§5).

## 1. What the sleeve is

An external signal (a US long with an entry, a stop and up to 12 targets) arrives over a local HTTP endpoint, is stored, and is traded in its own `signals` sleeve. Every entry passes the risk gate plus an LLM entry veto; a `signals/no-veto` shadow book takes every signal the gate admits, and the veto is judged against it (doc 66 S6, S7, G5). It is a counted trial. Only the primary book submits to Alpaca paper; the shadow is simulated.

## 2. Endpoint (built)

`npm run v2:signals` starts an always-on HTTP server (`server/apps/v2/signals/main.ts`) on `127.0.0.1`, port 8789 (`V2_SIGNALS_PORT`), writing to the v2 paper store (`--dry-run` for the dry-run store, `--store PATH` for another). It opens the store with the same migrating opener the cycle uses, so it can start before the cycle has applied migration 0077.

| Route | Does |
|---|---|
| `POST /api/v2/signals` | Validates, stores, queues. 201 with `{ signal, replayed: false }`; a repeat of a stored payload returns 200 with the stored signal and `replayed: true`. |
| `GET /api/v2/signals?limit=N` | Newest first; `limit` 1–200, default 50. |
| `GET /api/v2/signals/{id}` | One signal with its status history. |
| `GET /openapi.json` | The OpenAPI 3.0.3 document. |
| `GET /docs` | Swagger UI over that document. |

**No authentication, loopback only.** David ruled no auth until the VPS move brings an auth service. Until then the server binds `127.0.0.1` only (a hard-coded constant, not a setting), and refuses any request whose `Host` header is not `127.0.0.1:<port>` or `localhost:<port>` (403), so a web page cannot reach it by DNS rebinding. `POST` accepts `application/json` only (415 otherwise), so a browser form cannot send a simple cross-site request; bodies over 4,096 bytes are refused (413). Swagger UI loads its version-pinned assets from jsDelivr under Subresource Integrity hashes; the API itself makes no outbound call.

## 3. Payload (built)

`{ symbol, entry: number | [lo, hi], targets: number[], stop, size?, trail_after?, source?, received_at? }`, validated strictly (`server/apps/v2/signals/payload.ts`); any other field is refused.

- `symbol`: an upper-case US ticker, optionally with a class suffix (`BRK.B`).
- Every price is a finite positive number. `stop` < `entry` (the zone's low); `targets` has 1–12 entries, strictly ascending, all above the entry (the zone's high). US longs only.
- `size` (0–1) is **recorded, not used**: paper sizes every signal at full risk (§5).
- `trail_after` is **recorded, not implemented**: there is no trailing stop.
- `source`: 1–64 characters from a fixed set (letters, digits, space, `_ . : @ / -`), so it cannot carry markup or prompt text into the veto prompt.
- `received_at`: the sender's timestamp, ISO 8601 with a zone; stored as `sent_at`. The server stamps its own receipt time.

**Idempotency.** A signal's key is a digest of the parsed payload plus the sender's timestamp, or the UTC receipt date when there is none. The same payload sent twice the same day is one signal; the second POST replays the first. The key is the column `v2_signals.payload_digest`, `UNIQUE`.

## 4. Store and timing (built)

Migration 0077 adds two append-only tables (update and delete refused by trigger), owned by the v2 stage: `v2_signals` (one row per signal, the payload and its window) and `v2_signal_events` (a status history: `queued`, `processed`, `refused`, `failed`, each with a detail and a time). A signal's status is its latest event. `failed` does not close a signal: it stays due and is retried (§5, Retry).

At receipt the signal is classified against the US regular session from the existing market calendar (`UsEquityRegularHoursCalendar`, no hard-coded hours; half days close early): inside the session it is `in_session` and processed at once; outside it is `out_of_session` and processed at the next session open (`nextSessionOpen`). Both are stored as `session` and `process_after`, with a `queued` event. The calendar is hand-entered through 2027-12-31 and throws past its coverage, which the endpoint answers with 500.

## 5. Sleeve (built)

Code: `server/apps/v2/signals/processor.ts` (the processor), `server/apps/v2/signals/entry.ts` (entry plan, bracket target and quote fill), `server/apps/v2/execution/alpaca/alpaca-quotes.ts` (the latest-quote read), `server/apps/v2/signals/veto.ts`, `server/apps/v2/signals/loop.ts` (the always-on trigger), `server/apps/v2/run-lease.ts` (the lock), and `SIGNALS_SLEEVE_SPEC` in `server/apps/v2/signal/parameters.ts`.

- **Capital:** the sleeve's capital share is 70%: on a £10,000 paper year that is a £7,000 book, a £1,050 loss cap and a £70 daily cap (doc 66, 2026-09-27). The figures are derived from the capital config and the share (D8), never written in code. Both books, `signals/primary` and `signals/no-veto`, start at the share. The rules-based candidates (#1785) have no idle cash while this holds.
- **Loss budget, per sleeve:** David ruled on 2026-09-30 (#1941) that the budgets are split, not pooled. `signals/primary` and `debate/primary` each carry only their own sleeve's share of the yearly cap and the daily cap: signals 70% (£1,050 and £70 on a £10,000 year), debate 30% (£450 and £30), both derived from the capital config (`sleeveCapitalYear`). Each book steps down at a third and two thirds of its own cap and halts at all of it. A loss in one never changes the other's sizing. The account-wide pooled budget (#1799) is removed. The account cap still holds, because the shares of the sleeves that can hold a real fill sum to at most 1 (`assertCapitalShares`).
- **Sizing:** full R: risk 0.5% of equity over the distance from the limit to the signal's stop, whole shares, the 10% position cap and every existing cap (gross, ADV, loss-budget tiers, daily cap). The signal's `size` is journalled as `size_hint` and ignored.
- **Exit:** one bracket. The stop is the signal's stop; the target is the first target at least 2R above the limit, else the last target (`target_price` on the decision, which the risk gate uses in place of its ATR target). No ladder (#1853 stands), no time stop.
- **Entry:** classified against the last daily close before today. An entry at or below it enters as a GTC bracket with a limit parent; a zone is a limit at its high. An entry whose low is above the last close is a buy-stop. It enters as a GTC bracket with a `stop_limit` parent: stop (trigger) at the zone's low, limit at its high, and for a single entry both at the entry. David ruled this on 2026-09-30 (#1941), after one Alpaca paper probe accepted both a `stop` and a `stop_limit` bracket parent with the legs held (`docs/reviews/alpaca-stop-parent-probe-2026-09-30.md`). David ruled `stop_limit` over `stop` the same day because the limit caps the fill, so the gate's R (limit minus stop) stays the worst case. A plain `stop` parent fills at any price through a gap. A zone that straddles the close enters at its high as a plain limit. The risk gate refuses a trigger above the limit (`trigger_beyond_limit`) or at or below the stop (`trigger_at_or_past_stop`). The adapter rounds the trigger up to the tick grid, never above the limit, and refuses the bracket if the rounded trigger lands at or below the rounded stop. The shadow fills at the first quote (below).
- **Universe (#2024, 2026-10-08):** a signal is traded only for a current S&P 500 member, read from the constituent list the repo keeps (`data/bars/sp500-constituents.csv`, the trading date's row). An off-list symbol is refused as `not_in_universe` before the veto, the quote read or any entry, so neither book enters it. The liquidity screens are a fresh last close in the bar store (`stale_last_close`), the debate pool's movers floor of $50M dollar volume on the last bar (`MOVERS_MIN_DOLLAR_VOLUME_USD`, refused as `below_dollar_volume_floor` before the veto, the quote read or any entry, David 2026-10-08), and the risk gate's volume cap of 1% of the 20-bar average daily volume (`no_adv` without a covered window). Bars come from the existing bar store.
- **First-quote fill (#2024, 2026-10-08):** after the veto and just before the entry pass, the processor reads the Alpaca latest quote (`GET /v2/stocks/{symbol}/quotes/latest` on the data host, no `feed` parameter, so the account's own feed answers). The quote must be at or after the signal's `process_after`: its receipt in session, the next open out of session. An older quote, or one with no ask, fails the pass, and the retry reads again on the next pass. Both entry orders and the decisions carry `entry_quote` (`ask`, `bid`, `quoted_at`, `fill`). `fill` is the ask when the ask is at or below the limit and, for a buy-stop, at or above the trigger; otherwise it is null. The primary is the Alpaca bracket sent right after the read, and Alpaca fills it. The daily cycle books the shadow at `fill`, with fees but no modelled spread or impact, since the ask already crosses the spread, and stops it out if the fill day's bar reaches the stop. A null `fill` leaves the shadow resting (it still counts for `symbol_held`) until the next daily cycle, after the session that is the real leg's validity window, cancels it as a no-fill. A dry run reads no feed: its entries keep the daily-bar simulation (confirmed by David 2026-10-08) (no fill unless the high reaches a buy-stop's trigger; then a fill at the open or the trigger, whichever is higher, if that is at or below the limit; otherwise at the limit if the bar trades back down to it).
- **Session:** an in-session signal is processed at once; an out-of-session one waits for the next open (§4). A signal whose own session has passed is refused (`session_missed`). An entry that does not fill that session is cancelled by the next daily cycle, as every stale entry is.
- **Veto-rate cap (#2024):** after each processed signal, the processor reads the verdicts of the last 20 signals whose veto ran (pass or veto; `unavailable` is not a verdict). When 20 exist and more than 10% are vetoes (3 or more), it records a `veto_rate` fault (code `SIGNAL_VETO_RATE`, migration 0096) and logs `v2_signal_veto_rate` at error level. The same count is ledgered once per trading date. It is an alert, not a block: vetoes keep working above the cap. Like every fault kind, it counts against the fault-free weeks.
- **Retry (#2024):** a signal whose processing throws gets a `failed` event and stays due. Each later pass in its session (every 30 s) retries it. The veto runs once per signal: its verdict (`pass`, `veto` or `unavailable`, with the reason) is journalled in `v2_signal_vetoes` (migration 0099) before the quote is read, and every retry reuses it, so a retry makes no LLM call (David 2026-10-09). The one exception is a failed LLM call: that pass fails the signal and a later pass makes one more attempt, journalled in `v2_signal_veto_retries` and `v2_signal_veto_retry_verdicts` (migration 0100), whose verdict is then final. Its validity window is its own session. On the first pass after that session, it closes as `refused` with code `dropped`, journalled with scope `signal`, ticket #2024 and the last error. A retry that finds the signal's entry order closes it as `already_submitted`, so the date-free order id never sends a second order.
- **Veto:** the pinned judge model over the existing transport, under the secret guard (#1881) and the spend cap. The prompt carries the signal (symbol, entry, limit, stop, bracket target, targets, last close) and the last 20 daily bars at quoted prices, never account data. A veto skips the primary; the shadow enters regardless. When the veto cannot run (spend cap, call failure) the primary is skipped as `unavailable` and the shadow still enters (ruled by David 2026-09-30, #1941: skip, as built).
- **Refusals:** each is journalled with scope `signal` and the code as its parameter, and closes the signal as `refused`: `session_missed`, `dropped` (a failed signal whose session has passed, with its last error), `manual_control_paused`, `manual_control_halted`, `no_capital_config`, `not_in_universe` (not a current S&P 500 constituent, David 2026-10-08), `stale_last_close`, `below_dollar_volume_floor` (the last bar's raw close times its volume under $50M, David 2026-10-08, ticket #2024), `last_close_at_or_below_stop`, `symbol_held` (held or resting in a signals book or any broker-routed Alpaca book). A primary with no clean Alpaca reconcile journalled for the day is blocked (`reconcile_not_clean`) while the shadow trades. Both books' entries, like every sleeve's, are refused at the risk gate (`FX_YEAR_START_COVERAGE`, #2009) while the 1 January GBP/USD fix is more than 7 days before 1 January; their exits still run, priced at that fix.
- **Concurrency:** one lease row (`v2_run_lease`, migration 0078) serialises the processor and the daily cycle. The processor tries once and skips the pass if the cycle holds it; the cycle waits up to 15 minutes, then fails. A lease held by a dead process, or older than 6 hours, is taken over. Entry order ids are `v2-<book>-<symbol>-<signal id>`, with no date, so a replayed signal finds its order and is closed as `already_submitted`.
- **Liveness (#1951):** the process pings its own healthchecks.io check (`HEALTHCHECKS_SIGNALS_PING_URL`) from its poll timer, at most every 5 minutes and first a full 5 minutes after boot, so a process that exits inside that window, as under launchd's 30 s restart of a broken config, never pings and the check goes down. The fifth failed pass in a row pings `/fail`, and a pass open longer than 15 minutes holds the success ping until it ends, so a hung process alerts too. Doc 67 holds the setup.
- **Cycle:** the daily cycle runs the signals sleeve like any other (it decides nothing itself): it sweeps fills, reconciles, cancels stale entries and manages exits for both books. In the other direction, the cycle refuses any entry on a symbol that another broker-routed book holds or rests at the same venue (`symbol_held_by_broker_book`): one Alpaca account serves every such book.
- **Journal:** every signal event, decision (with the veto's verdict and reason in its payload), refusal, order and fill; the dashboard journal shows the signals books' decisions and the `signal` refusals.

### Known limits

- The daily cap binds at the next mark, not mid-session. The processor does not sweep fills intraday, so several same-day signals can together lose more than the £70 daily cap before the cycle sees it. David ruled on 2026-09-30 (#1941) to record this and let paper decide. It is fixed only if same-day signal clusters show up.
- A buy-stop that gaps through its limit need not fill: the `stop_limit` parent triggers and then rests at the limit, filling only if price trades back down to it. For a single-price entry the trigger and the limit are both the entry, so a gap-up open misses unless price returns. The daily cycle cancels an unfilled entry as stale.
- The probe sent `time_in_force: day`; the executor sends `gtc`, which was not probed. If Alpaca refuses a gtc stop-limit bracket, the entry is journalled `rejected`. The date-free order id then makes a later pass read it as `already_submitted`, so that signal is never retried.
- A zone that straddles the close enters at its high. This is recorded, not ruled.
- Only the first quote decides the shadow. A later quote in the session that reaches the entry does not fill it, though the resting real leg can still fill then. David confirmed this reading on 2026-10-08 (doc 66).
- The real leg's fill is Alpaca's. That Alpaca paper fills it from the same feed the quote is read from is not verified. David ruled on 2026-10-08 that a paper-week fidelity check compares the real leg's fill prices with the shadow's; it is not built yet (doc 66).
- The stop check on the shadow's fill day uses the whole day's bar, including the part before the quote. David confirmed this on 2026-10-08 (doc 66).
- A quote that is older than `process_after`, has no ask, or cannot be read (a data-host error or outage) blocks both legs: neither book enters, and the 30 s retry reads again until the session ends, when the signal is `dropped`. David ruled this fail-closed reading on 2026-10-09 (doc 66). The veto has already run by then; its journalled verdict is reused by every retry, so the retries spend no LLM budget.
- A veto that comes back `unavailable` because the LLM call failed (reason `llm_call_failed: …`) gets one more attempt on a later pass in the same session; neither leg enters until then, and the second verdict is final. An `unavailable` from the spend cap (reason `llm_spend_cap:<kind>`) is final on the first attempt, so the primary stays skipped and the shadow enters. David ruled this on 2026-10-09 (doc 66). The claim for the second attempt is journalled before the call, so a crash during it makes the retry `unavailable` and final rather than earning a third call. A call failure on the last pass of the session has no later pass: the signal is `dropped` and neither leg enters.
- `npm run v2:replay` does not re-run the signals sleeve: it compares the debate and arm 2 decisions, and leaves a day's signals rows out. The journalled verdict (`v2_signal_vetoes`) is what a signals replay would read in place of the LLM, but none is built yet.
- A retry after a partial entry, where one book's order was written and the other's was not, closes the signal as `already_submitted`. The book without an order never enters that signal.
- Classification uses the prior close. A stock that gaps below the stop in-session still gets its limit, which is then marketable at the open's price.
- A stale Alpaca entry whose cancel fails keeps `symbol_held` refusing that symbol until it is cleared.
